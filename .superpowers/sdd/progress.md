## Medium note update (important)

The Penpot MCP plugin connection dropped mid-Task-3 and had to be
reconnected. On reconnect, the server-side `storage` object was reset to
empty — but the actual Penpot file state (tokens, the Button component)
survived intact, since that's real Penpot document state, not `storage`.

**Consequence for all remaining tasks:** `storage` from earlier tasks
(`storage.colorTokens`, `storage.radiusTokens`, `storage.buttonComponent`,
etc.) can NOT be assumed to persist across a reconnect. Every task brief
from here on must have its implementer re-derive any needed `storage`
values from live Penpot state at the start of the task (e.g. re-fetch
tokens via `penpotUtils.findTokenByName(...)` into a fresh `storage.colorTokens`
map, re-find `storage.buttonComponent` via
`penpotUtils.findShape(s => s.name === 'Button' ...)` or by searching
`penpot.library.local.components`) instead of assuming the objects are
already populated. This "rehydration" step must run BEFORE checking "prior
state" sanity checks that used to just check `!!storage.xxx`.
